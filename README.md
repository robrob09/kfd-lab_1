# Расписание

Консольное приложение на Kotlin для лабораторной «Ничего не падает». Реализованы обязательные этапы: модель занятий, реестр с журналом, разбор файла и команды `period`, `type`, `errors`.

Условие: [docs/assignment.md](docs/assignment.md).

## Сборка и запуск

Нужны JDK 25 и Python 3.10+. В проекте используются Kotlin 2.4.10, Gradle 9.5.1 и JUnit 6.1.3. Gradle и Kotlin загружаются через Wrapper при первой сборке.

На этом компьютере Temurin JDK 25 установлен в `C:\Java\jdk-25`, кэш Gradle находится в `C:\Java\gradle-cache`.

Команды PowerShell выполняются из корня проекта:

```powershell
$env:JAVA_HOME = 'C:\Java\jdk-25'
$env:GRADLE_USER_HOME = 'C:\Java\gradle-cache'
.\gradlew.bat build :app:installDist

.\app\build\install\schedule\bin\schedule.bat period --file samples/clean.txt --from 2026-09-28 --to 2027-05-13
.\app\build\install\schedule\bin\schedule.bat type --file samples/dirty.txt --type EXAM
.\app\build\install\schedule\bin\schedule.bat errors --file samples/dirty.txt
```

На Linux/macOS нужно выбрать JDK 25 в `JAVA_HOME`:

```bash
bash ./gradlew build :app:installDist
./app/build/install/schedule/bin/schedule period --file samples/clean.txt --from 2026-09-28 --to 2027-05-13
./app/build/install/schedule/bin/schedule type --file samples/dirty.txt --type EXAM
./app/build/install/schedule/bin/schedule errors --file samples/dirty.txt
```

Во время разработки можно запускать приложение через Gradle:

```powershell
.\gradlew.bat :app:run --args="errors --file samples/dirty.txt"
```

Для проверки кодов завершения удобнее запускать созданный `schedule.bat`: `0` означает корректный файл, `1` — наличие отклонённых строк, `2` — неверные аргументы или ошибку чтения. В PowerShell код находится в `$LASTEXITCODE`. Для Gradle `run` коды `1` и `2` также означают неуспешное выполнение задачи.

## Модель

`Session` — sealed-интерфейс с датой и темой. Его реализуют четыре конечных обычных класса: `Lecture`, `Practice`, `Exam`, `Cancelled`. У отмены есть только дата и тема; свойств места и преподавателей у неё нет.

Обычные классы выбраны, чтобы не добавлять автоматически создаваемый `copy()`: каждый объект проходит проверки конструктора. Все свойства доступны только для чтения. Некорректные параметры приводят к `IllegalArgumentException` с объяснением.

Проверяется год `1..9999`, непустая тема, отсутствие управляющих и внешних пробельных символов. Для действующего занятия нужны допустимое место и хотя бы один преподаватель, для сдачи — два разных. Пустые имена, `-` и повторы запрещены. Внутренние пробелы допустимы, регистр значим. Значения не обрезаются и не исправляются.

Список преподавателей сохраняется через `java.util.List.copyOf`. Это отдельная неизменяемая копия: изменение исходного списка не влияет на занятие, а попытка изменить выданный список через `MutableList` заканчивается `UnsupportedOperationException`. Проверки выполняются по сохранённой копии.

## Реестр и делегирование

`MemorySessionRepository` хранит занятия в порядке добавления, включая повторы. `addAll` вызывает свой `add` для каждого элемента. `all()` возвращает защищённую копию списка: последующие добавления не меняют предыдущий снимок.

`AuditedSessionRepository` использует `SessionRepository by delegate`. Свойство `added` показывает число успешно добавленных занятий, `events` возвращает защищённый снимок журнала. Событие `AuditEvent` содержит `op` (`add` или `addAll`) и `count`.

Переопределить только `add` недостаточно: делегированный `addAll` выполняется на внутреннем реестре. Вызовы `add` внутри него обращаются к этому же внутреннему объекту, а не к обёртке. Поэтому обёртка отдельно переопределяет `addAll` и записывает одно событие на весь пакет после успешного возврата делегата. Повторного учёта нет.

Пустой пакет записывается с количеством `0`. `all()` событий не создаёт. Если делегат выбрасывает исключение, событие и счётчик не обновляются.

## Разбор и сообщения

`parseLine(n, line)` возвращает `ParseResult.Ok` с занятием или `ParseResult.Rejected` с номером строки и `Reason`. Причины содержат данные об ошибке; английский текст создают отдельные функции `reasonText` и `formatError`.

Порядок проверок: разделитель, число полей, первое пустое поле, дата, тип, количество преподавателей сдачи, остальные ограничения. Затем проверяются управляющие символы, внешние пробелы, поля отмены, место, элементы списка и повторы. В каждой группе выбирается первое поле, в списке — первый неподходящий элемент. Проверки общих ограничений используются и парсером, и конструкторами.

При подсчёте преподавателей сдачи пропускаются пустые, пробельные элементы и `-`, но повторы ещё учитываются. Поэтому `Ivanov,Ivanov` даёт ошибку повторного имени, а `Ivanov,-` — ошибку количества.

Обязательные сообщения воспроизводятся дословно:

```text
line N: invalid date "2026-13-45"
line N: empty required field "date"
line N: invalid field separator
line N: unknown session type "SEMINAR"
line N: type "EXAM" requires at least 2 teachers, got 1
line N: got 6 fields, expected 5
```

Дополнительные сообщения имеют такой же префикс `line N: `:

| Причина | Текст |
|---|---|
| Управляющий символ | `control character in field "F": "V"` |
| Внешние пробелы | `surrounding whitespace in field "F": "V"` |
| Неверное поле отмены | `type "CANCELLED" requires "-" in field "F", got "V"` |
| Недопустимое место | `invalid location "V"` |
| Недопустимый преподаватель | `invalid teacher "V"` |
| Повтор имени | `duplicate teacher "V"` |

`F` — имя поля, `V` — его исходное значение или выбранное имя преподавателя. В сообщениях `\` заменяется на `\\`, кавычка — на `\"`, управляющие и не-ASCII символы — на `\uXXXX` с заглавными шестнадцатеричными цифрами. Символ за пределами BMP записывается двумя UTF-16 последовательностями. Само содержимое занятия не меняется.

Команды читают весь файл и добавляют корректные занятия в реестр с журналом. Подходящие занятия или отказы печатаются по мере чтения, итог — только после успешного завершения чтения. Журнал в вывод не попадает. При ошибке чтения готовая точка входа печатает `Cannot read file`, ранее выведенные строки сохраняются, итог не печатается.

## Проверки

```powershell
.\gradlew.bat test
python -B tools/check_samples.py
python tools/verify.py
.\app\build\install\schedule\bin\schedule.bat errors --file examples/edges.txt
```

`tools/verify.py` запускается после `installDist` и сравнивает текст и коды завершения в 19 сценариях. Отчёт находится в `verification/acceptance.json`. Файл `clean.txt` содержит 200 корректных строк, `dirty.txt` — 500 строк с 164 отказами, `empty.txt` пустой.

Собственный файл `examples/edges.txt` содержит границы годов, отмену и строки с несколькими нарушениями, повтором имени, конечным пустым именем, пробелом перед именем и пустой строкой. Ожидаемый вывод — `examples/edges.errors.expected`, код завершения `1`. Этот пример также проверяется тестом.

Обязательные попытки сломать модель проверяются напрямую, без парсера:

| Попытка | Защита |
|---|---|
| Пустая или пробельная тема | Проверка конструктора |
| Год `0` или `10000` | Проверка конструктора |
| Действующее занятие без преподавателей | Проверка конструктора |
| Сдача с одним преподавателем | Проверка конструктора |
| Сдача с одинаковыми преподавателями | Проверка конструктора |
| Изменение исходного списка | Отдельная неизменяемая копия |
| Изменение списка, полученного из объекта | Неизменяемая коллекция |
| Обход через `copy()` | У обычных классов такого метода нет |

Дополнительно тестируются четыре корректных типа, границы годов и периода, внутренние пробелы и регистр, снимки реестра, журналирование, приоритет ошибок, экранирование, LF/CRLF, пустые файлы, ошибки вне фильтра и ошибка чтения после частичного вывода. Готовые тесты запуска сохранены.
